# BMS Monitor — frontend

React / строгий TypeScript. Живой экран батареи получает снимок через HTTP и обновления через Mercure. Production — только статические файлы, без Node/Vite/Docker.

Репозиторий: `git@github.com:lexwm/bms_monitor_forntend.git`.

- [Сборка, поставка и маршруты для DevOps](docs/deployment.md).
- [Снимок OpenAPI backend](contracts/openapi.json). Это копия, не самостоятельный источник контракта.
- [Правила разработки](AGENTS.md).

Локальная совместная разработка: `./bin/up` и `./bin/check` из корня workspace BMS_Monitor. Frontend может быть собран отдельно: все необходимые файлы входят в его репозиторий. Node 22, зависимости строго из `package-lock.json`; инструкции сборки находятся в deployment.md.

При изменении API скопировать `contracts/openapi.json` из backend в `contracts/openapi.json` этого репозитория (в общем workspace `./bin/sync-contract`), затем выполнить `npm run generate:api` через локальный контейнер. `npm run check:generated` проверяет соответствие типов/схем снимку. Общая проверка workspace дополнительно проверяет идентичность снимка backend. Generated-файлы не редактировать вручную.

## Дашборд

Единственный язык интерфейса — украинский, включая подсказки, ошибки и подписи для экранного диктора. Числа и даты форматируются по `uk-UA`, время — Киев. Текст интерфейса на другом языке считается ошибкой.

Состояние батареи определяется знаком исходного тока по подтверждённому владельцем правилу: положительный — «Заряджання», отрицательный — «Розряджання», ровно ноль — «Від мережі / без заряджання». Порог 1 А не применяется: даже +0,04 А означает зарядку, а −0,04 А — разрядку. Подпись о сети — согласованное обозначение нулевого тока этой установки, а не показание отдельного датчика сети. При отсутствии показания тока, устаревших данных или ошибке связи состояние объясняется отдельно, без выдачи сохранённого режима за текущий.

Утверждённый графитовый макет с золотом/серебром и индикатором 3B («Дуга под стеклом»). На узком экране карточки перестраиваются в одну колонку, ток и мощность остаются рядом. Меню скрывается; анимации учитывают системную настройку уменьшения движения.

Текущие значения приходят через существующую подписку Mercure. Графики мощности, тока и полнота истории используют один выбранный период: 10 минут (по умолчанию), 1, 12 или 24 часа, 30 дней, квартал либо год. Кнопки находятся в заголовке мощности. Снимок получает `GET /api/v1/battery/history/series?range=…`; границы последних трёх и двенадцати календарных месяцев рассчитывает backend. Длинные периоды показывают среднее и приглушённые границы минимума/максимума. Частично заполненный интервал показывается отдельно; ожидающий подготовки интервал не считается пропуском измерений или нулём. Пока часть истории не подготовлена, общий процент полноты неизвестен; объём подготовленной части указан отдельно.

История обновляется по сигналам одной существующей подписки Mercure (`telemetry.updated.v1` и независимое `history.updated.v1`), при смене периода, восстановлении связи или кнопке «Оновити знімок». Фоновые сигналы объединяются: не чаще одного запроса за 15 секунд для 10 минут/1 часа и 60 секунд для сводных периодов; один отложенный запрос сохраняет последний сигнал. Без сигналов запросов нет. Выбор периода загружает его сразу, не переподключая канал и текущие показатели. Скрытая вкладка приостанавливает историю; при возвращении выполняется одно восстановление выбранного периода. При загрузке или ошибке сохраняется подписанный предыдущий снимок; выбранная кнопка обозначает запрошенный период. Задержавшийся ответ прежнего выбора не заменяет последний выбор. Смена готового снимка плавно сменяет линии и оси за 220 мс без изменения размеров графика; настройка уменьшения движения отключает переход. История напряжения отсутствует в текущем контракте, поэтому вместо демонстрационного графика напряжения показан ток.

«Налаштування батареї» — отдельная страница (`#configuration`, пункт главного меню), а не блок под дашбордом; серверных маршрутов она не требует. Значения разложены по вкладкам и двум колонкам, пороги защиты сведены в таблицы «порог / восстановление / задержка». Группировка задаётся кодами полей в `src/configurationLayout.ts`; всё, что туда не попало (неизвестные коды и повторы полей), остаётся на вкладке «Службові» вместе с источником и исходными байтами. Пустые вкладки не показываются.

В подробной истории линии не соединяются через gaps, невалидные записи, отсутствующие значения показателя, смену boot_id и промежутки больше 10 секунд. В сводной истории линия соединяет только полностью покрытые непрерывные интервалы одного показателя при совпадении загрузки источника и расстоянии между граничными измерениями не более 10 секунд. По сводным данным нельзя восстановить точные границы коротких пропусков. Пропуски отображаются нейтральной штриховкой; отсутствие отдельного показателя — разрывом его линии. Нулевые измерения остаются нулями, неизвестные — прочерками. Полнота истории берётся из API и относится ко всем измерениям, а не к непрерывности работы батареи. Состояние данных и их возраст показаны в шапке, отдельного блока пояснений под ней нет; при обрыве канала обновлений там же появляется пометка «Канал оновлень відновлюється». В меню два пункта: «Огляд» и «Налаштування батареї». Значок сайта и манифест лежат в `public/assets/` (SVG с прозрачным фоном и PNG 180/192/512, полученные из него).

Под ячейками в одном ряду стоят компактные блоки: температуры, расчётное время до полного заряда или разряда, счётчик циклов зарядки из показаний батареи (`battery.cycles`; при отсутствии значения — прочерк) и полнота истории. Графики мощности и тока занимают всю ширину под ними. Расчётное время (`src/estimate.ts`) — грубая линейная оценка: при разряде остаток ёмкости делится на текущий ток, при заряде — недостающая до заявленной ёмкость. Оно показывается только по свежим показаниям; при нулевом токе, устаревших данных или отсутствии нужных значений — прочерк с пояснением. Восемь горизонтальных ячеек расположены в два ряда по четыре, напряжение показано внутри с тремя знаками после запятой; заполнение показывает напряжение, не процент заряда; температурные полосы — шкалу без оценки безопасных порогов.
